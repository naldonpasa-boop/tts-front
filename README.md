# tts-front

Фронтенд виртуального игрового стола для D&D (MVP). Веб-приложение отрисовывает
квадратную сетку 100×100 и пассивно отображает на ней токены, координаты которых
приходят с сервера. Архитектурные решения зафиксированы в [ADR.md](./ADR.md).

Стек: TypeScript, Vite, [PixiJS 8](https://pixijs.com/), [pixi-viewport](https://github.com/pixijs-userland/pixi-viewport).

## Требования

- Node.js ≥ 20 (проверено на 24.x)
- npm ≥ 10

## Запуск

```bash
npm install
npm run dev
```

Откройте адрес, который напечатает Vite (по умолчанию `http://localhost:5173`).
По умолчанию приложение работает с **dummy**-бэкендом: статический снапшот из
50 токенов, сервер не нужен.

Чтобы отдать приложение другим устройствам в локальной сети:

```bash
npm run dev -- --host
```

## Управление

| Действие | Мышь / тач |
| --- | --- |
| Панорамирование | зажать ЛКМ и тянуть / один палец |
| Зум | колесо мыши / pinch |

Камера ограничена границами поля; минимальный зум — «всё поле на экране», максимальный — 4×.
В левом нижнем углу показывается статус: режим API, версия последнего снапшота, число токенов.

## Подключение к реальному бэкенду

Реализация клиента выбирается переменными окружения (см. `.env.example`):

```bash
# .env.local
VITE_SCENE_API=real
VITE_API_BASE_URL=http://192.168.1.10:8080
```

либо одноразово:

```bash
VITE_SCENE_API=real VITE_API_BASE_URL=http://192.168.1.10:8080 npm run dev
```

Клиент опрашивает `GET {VITE_API_BASE_URL}/api/scene/snapshot` каждые 200 мс и ожидает:

```json
{
  "snapshotVersion": 42,
  "sceneObjects": [
    { "id": 1, "x": 130, "y": 4115 }
  ]
}
```

- `x`, `y` — целочисленные мировые координаты (1 клетка = 64 единицы). Клиент
  сам определяет клетку целочисленным делением и ставит токен в её центр.
- `snapshotVersion` — монотонно растущая версия. Снапшоты с версией не больше
  уже применённой игнорируются, сцена перерисовывается только при изменениях.
- Бэкенд должен разрешать CORS для origin фронтенда (либо фронт нужно
  раздавать с того же хоста). Авторизация в MVP отсутствует по ТЗ.

При недоступности бэкенда статус подсвечивается красным, опрос продолжается и
восстановится автоматически.

## Структура проекта

```
src/
  main.ts                 точка сборки: API → Poller → Renderer
  config.ts               размеры сетки, интервал опроса, режим API, цвета
  api/
    types.ts              контракт снапшота
    SceneApi.ts           интерфейс клиента бэкенда
    RealSceneApi.ts       HTTP-реализация, параметризована базовым URL
    DummySceneApi.ts      статический снапшот (используется в MVP)
    validate.ts           runtime-проверка ответа сервера
    index.ts              createSceneApi(mode, baseUrl)
  app/
    ScenePoller.ts        short polling, последовательные запросы, фильтр по версии
  render/
    SceneRenderer.ts      всё, что знает про PixiJS: Application, Viewport, спрайты
    gridTexture.ts        текстура одной клетки для TilingSprite
    Emitter.ts            типизированный on/off
public/
  token.svg               единственный плейсхолдер токена
```

`SceneRenderer` не знает, откуда берутся данные: снаружи вызывается
`updateScene(snapshot)`, а о событиях внутри canvas (`sceneUpdated`,
`tokenTapped`) он сообщает через `on()/off()`. Это позволяет позже встроить его
в React/Vue или заменить polling на WebSocket, не трогая слой отрисовки.

## Отладка

В dev-режиме в консоли браузера доступен объект `window.__tts` с
`renderer`, `poller`, `api` и `config`. Например, применить произвольный
снапшот вручную:

```js
__tts.renderer.updateScene({ snapshotVersion: 999, sceneObjects: [{ id: 1, x: 0, y: 0 }] });
```
